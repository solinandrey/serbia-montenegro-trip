# CLAUDE.md

Контекст для работы над этим репозиторием. Читать целиком перед первой правкой.

## Что это

Страница-план поездки на троих: Белград (2–13 сентября 2026), поезд Белград-Центр → Бар,
две недели по Черногории на машине. Первая неделя в Черногории свободная, вторая рабочая —
двое из троих работают удалённо днём в будни.

Не лендинг и не путеводитель. Рабочий документ, который правят втроём во время поездки.
Ценность страницы — в конкретике: суммы, времена, названия, «сюда не суйся». Всё, что звучит
как текст турагентства, из проекта вырезается.

Все названия по-русски: Белград, Черногория, Ловчен, Жабляк, Никшич. Сербское написание
из текстов убрано — читают трое русскоязычных, а не местные.

## Файлы

```
index.html    вёрстка, стили, вся логика; справочные блоки в массиве SEGMENTS
plan.json     данные: чеклист, пункты плана по отрезкам, заметки

```

Сборки нет, зависимостей нет, npm не нужен. Три файла, ванильный JS, шрифты с Google Fonts.

## Запуск

```bash
python3 -m http.server 8000   # http://localhost:8000
```

Через `file://` не работает: браузер блокирует `fetch('plan.json')`. Продакшн — GitHub Pages
из ветки `main`, root.

## Модель данных

`plan.json` — единственный источник правды для изменяемого содержимого:

```jsonc
{
  "version": 1,
  "checklist": [ { "id": "c01", "text": "…", "done": false } ],
  "segments": {
    "beograd": [ { "id": "b01", "text": "…" } ],
    "voz":     [ … ],
    "sever":   [ … ],
    "more":    [ … ]
  },
  "notes": [ { "id": "n01", "segment": "sever", "author": "…", "text": "…", "ts": 1757000000000 } ],
  "links": [ { "id": "l01", "segment": "beograd", "title": "…", "url": "…",
               "phone": "…", "address": "…", "ref": "…", "note": "…" } ]
}
```

Ключи `beograd` / `voz` / `sever` / `more` захардкожены в `SEGMENTS` внутри `index.html`.
Переименование ключа ломает связь плана с отрезком — если добавляете отрезок, добавляйте
в оба места одним коммитом.

`links` — ссылки, заметки, брони, телефоны и адреса, вид «Под рукой». Обязательны только
`id` и `title`, остальные поля пустыми не рендерятся. Есть необязательный `icon` — один-два
символа, режется `cleanIcon()`. Ссылки — не отрезок маршрута, поэтому в `SEGMENTS` им
делать нечего.

`segment` здесь работает как **тег**: `null` или отсутствие — «Общее». Список плоский,
не сгруппированный: сверху чипы-фильтры по тегам со счётчиками, показываются только те
теги, где что-то есть. Было пять групп с пятью одинаковыми формами — экран состоял
из пустых полей, это переделано.

Форма одна на весь вид и составная: название крупной строкой, ниже ссылка, тег и кнопка.
Что за ссылка добавлена, не угадываем — название вводят руками, потому что глазами ищут
именно его. Ссылка необязательна: «Страховка, полис в почте» — нормальная запись.

**Два необязательных поля есть у любого элемента** (пункт плана, пункт сборов, заметка,
запись «Под рукой»):

```jsonc
"ts": 1786987911858,                          // создание или последняя правка
"react": [ { "who": "Андрей", "kind": "+1" } ] // +1 и ?, только план и заметки
```

Обоих может не быть: в базе лежат элементы, созданные до этих полей. Рендер обязан это
переживать, элементы без `ts` считаются старыми и не подсвечиваются. `ts` ставит `touch()`
при создании и при inline-правке. Реакция `ts` не трогает: это не правка содержимого.

**Новый ключ верхнего уровня добавляется в шести местах.** `plan.json`, `seed()`,
`server/plan.seed.json`, `mergePlan()` и `normalize()` в `index.html`, `validPlan()`
на сервере. Пропустите `mergePlan()` — данные молча исчезнут через 20 секунд при первом
`pullShared()`, и это будет выглядеть случайным багом. Пропустите `normalize()` — страница
упадёт у всех, у кого в базе лежит план постарше. Проверку на сервере писать мягко
(«если поле есть, оно массив»), иначе сервис начнёт отвергать планы, которые сам же отдал.

Функция `seed()` в `index.html` дублирует стартовые данные на случай, когда `plan.json`
не прочитался. При правке `plan.json` она расходится с ним, и это нормально: `plan.json`
всегда выигрывает, когда доступен.

## Откуда берётся план

Четыре источника, страница перебирает их сверху вниз и останавливается на первом живом:

1. **Общий план на сервере.** Основной режим. Пароль лежит в браузере (`trip:key`), план —
   в Postgres на Railway. Правки видны всем троим, чужие подтягиваются каждые 20 секунд
   и при возврате во вкладку. Статус в шапке: «Общий план».
2. **Артефакт Claude.** `window.storage` есть — состояние в общей памяти по ключу
   `trip:beograd-crnagora:v1`.
3. **localStorage браузера.** Сервер недоступен или пароль не введён. Правки переживают
   перезагрузку, но у каждого свои. Статус честно об этом пишет.
4. **`plan.json` из репозитория.** Исходный слепок, он же то, чем сервер засевается на пустой базе.

`sessionStorage` не использовать. Персональное (имя автора заметок) — `window.storage`
с `shared:false`, общее — `shared:true`.

## Общий план: сервис

```
server/index.js        API: GET /plan, PUT /plan, GET /health
server/plan.seed.json  копия plan.json, засевает пустую базу при первом старте
```

Railway, проект `balkan-trip-api`, два сервиса: `api` и `Postgres`. Адрес
`https://api-production-aa10.up.railway.app` захардкожен в `index.html` (константа `API`).

Переменные сервиса: `TRIP_PASSWORD` (общий пароль на троих, без него сервис не стартует),
`ALLOW_ORIGIN` (список origin через запятую — Pages и localhost), `DATABASE_URL`
(ссылка на Postgres).

**Ревизии — не украшение.** `PUT` принимает номер ревизии, который клиент прочитал.
Если за это время кто-то записал своё, сервер отвечает `409` и текущим планом; клиент
сливает по `id` (`mergePlan`) и повторяет. Убрать ревизии = трое в дороге затрут правки
друг друга. Удалённое в сессии держится в `tomb`, иначе слияние воскрешает удалённое.

**Реакции сливаются отдельно.** `mergeList()` при совпадении `id` берёт свою версию
элемента — для текста это верно, для реакций это потеря: двое жмут «+1» одновременно,
и одна реакция исчезает. Поэтому `mergeItem()` объединяет `react` по паре (`who`, `kind`)
через `mergeReact()`. Это главное место, где фича тихо не работает; проверять двумя окнами.

**Таблицы две.** `plan` — текущее состояние (`rev`, `data`, `author`, `updated_at`).
`plan_rev` — снимок на каждую удачную запись, хранится последние 50, старые чистятся
тем же запросом. Обе создаются в `init()` через `if not exists`: сервис катится
в работающую базу.

Эндпоинты: `GET /plan` отдаёт `rev`, `plan`, `author`, `updated_at`. `PUT /plan` принимает
ещё и `author` — это подпись, а не доступ, доступ даёт только пароль. `GET /history` —
список ревизий без снимков, `GET /history/:rev` — снимок целиком. `GET /og?url=…` —
карточка ссылки. Все под тем же паролем и тем же CORS; при добавлении пути не забыть
про проверку 404, иначе всё, кроме перечисленного, отвечает «нет такого пути».

**`/og` ходит по чужой ссылке от имени сервера**, поэтому `safeTarget()` пускает только
http/https наружу и режет localhost, `.internal`, `.local` и приватные диапазоны
(`127.`, `10.`, `192.168.`, `169.254.`, `172.16–31.`). Убрать эту проверку — открыть
сервер для похода внутрь инфраструктуры. Ответы лежат в `og_cache` неделю.

Много сайтов карточку не отдают: Airbnb возвращает страницу-редирект, Booking закрыт.
Это норма, а не поломка. Клиент рисует превью, только если пришли картинка или описание;
заглушки вида «Переход на ru.airbnb.com» отбрасываются, остаётся обычная ссылка.

Разницу между ревизиями считает клиент (`diffPlans`), сервер снимки только хранит.

Деплой: `cd server && railway up --service api`.

Репозиторий публичный, адрес API виден в исходнике. Единственная защита — пароль,
он же на чтение. Менять так: `railway variables --service api --set TRIP_PASSWORD=…`,
после чего все трое вводят новый (кнопка «Подключить общий план»).

## Виды: на экране всегда один

Главное правило структуры. Страница не свиток, а семь видов; одновременно виден ровно
один, остальные скрыты атрибутом `hidden`.

Пять из них — места на маршруте, и они живут на дороге: `check` (сборы), `beograd`, `voz`,
`sever`, `more`. Два оставшихся местами не являются и стоят рядом с дорогой отдельными
ссылками: `links` («Ссылки · брони · телефоны», заголовок вида «Под рукой») и `repo`
(«Файл плана»). Ставить их остановками на дороге нельзя — на карте это не точки,
плюс на 375 px полоса и так впритык.

Вид держится в хеше: `#sever` открывает север, ссылку можно кинуть в чат. Если хеша нет,
`nowView()` выбирает отрезок по сегодняшней дате, а до поездки открывает сборы. `nowView()`
возвращает только отрезки маршрута: `links` и `repo` не должны открываться сами.

**Хеш составной.** `parseHash()` режет его по `&` и разбирает части: одна — вид, другая —
`key=…` с общим паролем. Ссылка `#sever&key=ПАРОЛЬ` открывает север и подключает общий план.
Не сверять весь хеш со списком `VIEWS` целиком — так `#sever&key=…` не откроет ничего.

Пароль из ссылки забирается в `takeKeyFromHash()` до первого `load()`, кладётся в
`localStorage` и немедленно вычищается из адреса через `history.replaceState`. Только хеш,
не query string: query уезжает в логи хостинга, хеш до сервера не доходит. Кнопка
«Подключить общий план» с `prompt` остаётся — ссылка её не заменяет.

Добавляете вид — правите четыре места одним коммитом: массив `VIEWS`, ссылку в навигации,
`<section data-panel="…">` в `main` и, если у вида есть свои данные, ключ в `plan.json`.

## Что нового с прошлого захода

`trip:seen` в `localStorage` — момент прошлого визита. Всё, у чего `ts` новее, помечается
меткой у строки и счётчиком в навигации.

**`trip:seen` обновляется на `pagehide` и через минуту после открытия, а не при загрузке.**
Иначе метки исчезнут раньше, чем человек успеет их прочитать, и вся затея бессмысленна.

Своё не подсвечиваем: `trip:mine` хранит id того, что правил ты сам. Отдельного поля
«автор» у элементов нет, и заводить его ради этого не нужно.

Имя подписи (`trip:me`) лежит в `localStorage`, а не только в памяти вкладки: иначе после
перезагрузки все трое становятся «без имени», и строка «кто правил последним» врёт.

## Ссылки внутри текста

`linkify()` делает кликабельными http/https/tel в пунктах плана, чеклисте и заметках —
это места, куда скидывают находку, и мёртвый текст там ломает смысл.

Порядок строгий: сначала `esc()`, потом `linkify()` по уже экранированной строке. Наоборот —
дыра. В `href` попадают только `http`, `https` и `tel`; `javascript:` и `data:` не проходят
по самому регулярному выражению, а не по чёрному списку. Показывается домен и обрезанный
хвост, полный адрес — в `title`.

## Дизайн-токены

Определены в `:root`. Новые цвета не вводить без причины, акцент на странице ровно один:

```
--paper #FFFFFF   --surface #F5F5F5   --surface-2 #E9E9E9
--ink #0D0D0D     --ink-2 #4A4A4A     --ink-3 #727272
--accent #E01B00  --quiet #5A5A5A     --alert #C81200
```

**Тема одна и она светлая.** Тёмной нет и заводить не надо: в `:root` стоит
`color-scheme: light`, блока `prefers-color-scheme: dark` в файле нет, `theme-color`
один. Она была, и её дважды просили убрать — на телефоне с системной тёмной темой
страница уезжала в чёрное, хотя нужен белый фон. Не возвращать.

Высокий контраст: белое, почти чёрное, красный. Цветной ровно один — красный.
Всё остальное нейтрально, и это не случайность:

- `--accent` (красный) — **действие и внимание**: кнопки, метка «новое», активная реакция,
  точка и пройденный участок дороги, стрелка в заголовке, контур фокуса.
- `--quiet` (серый) — **категория и метаданные**: подписи справочных полей, теги записей,
  автор заметки. Раньше тут была морская зелень; в монохроме второй цвет лишний.
- `--alert` — дедлайн и наведение на «Убрать». Тоже красный, но темнее: это тот же смысл
  «внимание», разводить их в разные цвета не нужно.

Левые полосы заметок и полосы отмены — нейтральные (`--ink-3`, `--ink`), не красные.
Иначе красным заливается вся страница и акцент перестаёт работать.

**Контраст проверять числами, а не на глаз.** Текущие значения: основной текст 19,4:1,
красный 4,85:1, текст на красной кнопке 4,85:1, мелкие кнопки правки 4,81:1.
Минимум AA — 4,5:1; `--ink-3` пришлось затемнить с `#787878` именно поэтому.

Шрифты: Geist (заголовки и текст), Geist Mono (всё числовое: времена, цены, даты, километры).
Правило простое — если это число или код, оно моно. Оба шрифта берутся с Google Fonts
и оба несут кириллицу; при замене шрифта это проверять первым делом, иначе страница
падает в системный (у Space Grotesk кириллицы нет).

Скругления одной шкалой, значения только из токенов, произвольных чисел в коде нет:

```
--r    12px   блоки: карточки, панели, поля справки
--r-sm  8px   элементы управления: кнопки, поля ввода, чипы, реакции
--r-xs  5px   мелочь: чекбокс, метки «новое», теги, контур фокуса
```

Прямые углы были до августа 2026, отменены по прямой просьбе. Градиентов и теней нет.

Профиль высот убран в августе 2026: вертикальная ось читалась только с объяснением,
горизонтальная не значила ничего, а занимал он 390 px над содержанием. Не возвращать
без ответа на вопрос «за что отвечают оси».

## Движение

Три вещи, и все мотивированы:

1. `.rise` — блоки шапки лесенкой при загрузке, порядок чтения в первый момент.
2. `.arrive` + `stepin` — содержимое вида появляется лесенкой при переключении отрезка.
   Индекс задаётся инлайновым `--i` в цикле рендера.
3. Точка на дороге едет между остановками (`travelTo`, rAF + `getPointAtLength`).

**`.arrive` снимается через 1,4 секунды.** Рендер полностью пересобирает DOM на каждую
правку, и без снятия класса лесенка проигрывалась бы заново каждый раз, когда кто-то
поставил галочку. Это раздражает сильнее, чем радует.

Остальное — переходы состояний на `:hover`, `:active`, `:checked` плюс подъём карточки
на 2 px под курсором. Скролл-слушателей нет, по скроллу ничего не двигается.
`prefers-reduced-motion: reduce` гасит всё перечисленное.

## Тон текстов

Пишем как местный, который объясняет знакомому за столом. Прямо, с мнением, с цифрами.

Так: «Внутри старого Котора не селиться: акустика колодца, бары до трёх, машину девать некуда.»
Не так: «Старый город Котора подарит незабываемую атмосферу.»

Кнопки и подписи — активным залогом, тем же словом на всём пути действия. «Скачать plan.json»,
а не «Экспорт». Пустое состояние — приглашение, а не извинение.

## Что нельзя ломать

- Числа в справочных блоках (`SEGMENTS[].facts`) — это проверенные факты, а не рыба.
  Меняются только вместе с проверкой источника, в коммите указывать откуда.
- Клавиатурная доступность: `:focus-visible` с жёлтым контуром, все действия достижимы табом.
- Мобильная вёрстка: чеклист схлопывается в одну колонку на 820px, полоса видов уезжает
  в горизонтальный скролл, кнопки правки на тач-устройствах видны всегда (`@media (hover:none)`).
- `prefers-reduced-motion` уважается.
- Удаление всегда с отменой. Кнопки «Убрать» на телефоне видны постоянно, промахнуться легко,
  поэтому любое удаление кладёт элемент в `offerUndo()` и его можно вернуть на то же место
  в течение 25 секунд. Не убирать ради упрощения.
- Текст пункта — часть зоны нажатия чекбокса (`<label class="tick">`). Мёртвых зон в строке
  быть не должно.
- В режиме репозитория несохранённые правки предупреждают при уходе со страницы
  (`beforeunload`). Правки живут только во вкладке, терять их молча нельзя.
